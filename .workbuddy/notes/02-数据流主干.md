# 02 - 数据流主干：一条 TCP 请求的完整旅程

> 走读时间：2026-10-22
> 场景：客户端 `curl --socks5 127.0.0.1:10808 https://example.com`，走 01b 的 config-demo.json
> 涉及文件：`proxy/socks/server.go` → `app/dispatcher/default.go` → `app/proxyman/outbound/handler.go` → `proxy/freedom/freedom.go`

## 总览：六步旅程

```
[0] proxyman/inbound worker 接受 TCP，造 session.Inbound{Source,Gateway} 入 ctx
    → 调 socks Server.Process(ctx, network, conn, dispatcher)     server.go:65
[1] socks 握手        server.go:82   processTCP → Handshake 解出 dest
[2] Dispatch 入口     default.go:203 造双管道 + 嗅探 goroutine，立即返回
[3] 嗅探              default.go:222 偷看首包 → TLS SNI/HTTP Host → 替换 dest
[4] 路由决策          default.go:300 routedDispatch → PickRoute → tag
[5] 出站转交          handler.go:174 h.proxy.Process(ctx, link, h)
[6] freedom 拨号对拷  freedom.go:95  Dial + 双向 buf.Copy → 数据回流
```

## Step 1 - socks 握手（server.go:82 processTCP）

```go
svrSession := &ServerSession{config, address, port, clientAddress...}
request, err := svrSession.Handshake(reader, conn)   // :101
dest := request.Destination()                        // :122 例如 example.com:443
```

- `reader` 是 `buf.BufferedReader` 包装的 conn——先握手后透传，必须带缓冲。
- 握手成功前不回 SOCKS 应答：`handshakeFinalizingDispatcher`（:133,149）包了一层——**等 `Dispatch()` 返回且链路建立，才发"CONNECT succeeded"**。否则回包成功但后面路由失败，客户端会以为代理坏了。

## Step 2 - Dispatch 入口（default.go:203）★ 本课核心

```go
func (d *DefaultDispatcher) Dispatch(ctx, destination) (*transport.Link, error) {
    ob := &session.Outbound{Target: destination}
    ctx = session.ContextWithOutbound(ctx, ob)        // 目标放进 ctx
    inbound, outbound := d.getLink(ctx)               // 造两根管道
    if !sniffingRequest.Enabled {
        go d.routedDispatch(ctx, outbound, destination)
    } else {
        go func() { /* 嗅探 → 可能替换 dest → routedDispatch */ }()
    }
    return inbound, nil                               // 立刻返回，不阻塞握手
}
```

**getLink 的管道配对**（default.go:135）—— inbound 和 outbound 各持半副耳机：

```
pipe.New() × 2 → uplink(client→remote), downlink(remote→client)

inboundLink  = {Reader: downlinkReader, Writer: uplinkWriter}     ← socks 拿走
outboundLink = {Reader: uplinkReader,   Writer: downlinkWriter}   ← freedom 拿走
```

`transport.Link` 只是 `{Reader, Writer}` 二元组。**入站和出站永远不见面，只通过内存 pipe 交换数据**——这就是为什么任意入站协议可以接任意出站协议，也是链式代理的基础。
（顺带：这里还给带 email 的用户挂 `SizeStatWriter` 计数器，stats 流量统计的挂点。）

## Step 3 - 嗅探：IP 流量变回域名流量（default.go:222-240, sniffer:245）

为什么需要：客户端直接连 IP 时（浏览器常用 IP 直连），路由规则里的 `geosite:cn` 没法匹配——**必须从流量内容里把域名偷回来**。

机制（`cachedReader` :30）：
1. `Cache()` 先读一段进缓存（不消费管道），喂给 sniffer；
2. 识别 TLS ClientHello 的 SNI / HTTP Host；
3. 200ms 总预算、最多 2 次尝试（`ErrNoClue`/`ErrProtoNeedMoreData` 各计一次）；
4. 嗅到域名 → `destination.Address = domain`（:234），后续路由按域名匹配；
5. 缓存数据随后原样流向出站，**一字节不丢**。

## Step 4 - 路由决策（default.go:300 routedDispatch）

优先级链：
```
① session 强制 tag（平台/API 预设）       :303
② d.router.PickRoute(ctx) → tag           :315  （03 课的主菜）
③ 都没有 → GetDefaultHandler()            :341  （App 列表第一个出站）
最后 access log 记 Detour → handler.Dispatch(ctx, link)  :362
```

## Step 5 - 出站 Manager 与 handler 转交

- `Manager.GetHandler(tag)` 就是张 map（proxyman/outbound/outbound.go:90）；`AddHandler` 时第一个无 tag 或默认的成为 defaultHandler（:105）。
- `Handler.Dispatch`（handler.go:153）做两件事：可选的 senderSettings 域名解析 / mux，然后：

```go
if err := h.proxy.Process(ctx, link, h); err != nil { ... }   // :174 ★
```

**Handler 把自己当 dialer 传给协议实现**——handler 同时实现了 `internet.Dialer`（:188 Address() 等），freedom 只管 `dialer.Dial(ctx, destination)`，完全不知道底层是 TCP 还是 mKCP。

## Step 6 - freedom：直连出站（freedom.go:95 Process）

```
① 从 ctx 取回 outbound.Target（嗅探替换过的域名还在）
② 可选 DestinationOverride / ProtocolReplacement / useIP 域名解析
③ retry.ExponentialBackoff(5, 100).On(dialer.Dial)   :129 指数退避重试拨号
④ 双向对拷（和 socks 侧完全对称）：
   requestDone:  link.Reader(客户端来) → conn
   responseDone: conn → link.Writer(回客户端)
⑤ task.Run(ctx, requestDone, OnSuccess(responseDone, Close(output)))
```

两侧的 `buf.Copy` + `UpdateActivity(timer)` 对拷：空闲超时 → cancel → 双向中断。
数据回流路径：远端 → conn → freedom 写 downlinkWriter → pipe → socks 的 responseDone 读 link.Reader → 写回客户端 conn。

## 本课关键设计（4 条）

1. **管道化解耦**：`transport.Link` + `pipe` 让入站/出站互不相识，任意组合。
2. **接口即边界**：入站只见 `routing.Dispatcher`，出站协议只见 `internet.Dialer`+`Link`。
3. **嗅探是路由的前置增强**：IP → 域名还原，让 geosite 规则对"IP 直连"流量生效。
4. **异步 Dispatch**：造完管道立即返回，嗅探/路由/拨号全在 goroutine；代价是错误只能通过关闭管道（Interrupt）传导回入站侧。

## 速记 + 自测

> **速记**：`握手解出 dest → Dispatch 造双管即返 → 嗅探偷域名 → PickRoute 拿 tag → Manager 查 handler → proxy.Process(ctx, link, dialer=自己) → Dial + 对拷`。

1. 为什么 socks 侧要包一层 `handshakeFinalizingDispatcher`？
   （答：SOCKS 成功应答必须等出站链路真正建立后再发，否则客户端会在代理失败时误以为连接成功。）
2. 嗅探失败（超时/不认识协议）会断连接吗？
   （答：不会。destination 保持原样（IP），照样走路由，只是退化成按 IP 匹配规则。）
3. 如果路由选中的 handler 在 freedom 拨号失败，客户端感知到什么？
   （答：link 被 Interrupt/Close → socks 侧 buf.Copy 报错 → 连接断开，错误经 log 输出，客户端只看到连接被重置。）
