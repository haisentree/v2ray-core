# 01 - 启动流程：从 `v2ray run` 到数据面就绪

> 走读时间：2026-10-22
> 涉及文件：`main/main.go` → `main/commands/run.go` → `config.go`(根) → `infra/conf/serial/loader.go` → `v2ray.go` → `common/type.go` → `main/distro/all/all.go`

## 全链路图

```
main.go
 └─ base.RegisterCommand(run/version/test) → base.Execute()
     └─ executeRun()                     main/commands/run.go:83
         ├─ ① setConfigFlags()           注册 -c/-d/-format/-r
         ├─ ② plugins 预登记             必须在 Flag.Parse 前（pprof 插件注册自己的 flag）
         ├─ ③ getConfigFilePath()        配置文件定位，优先级回退链（见下）
         ├─ ④ startV2Ray()               LoadConfig → core.New（只装配，不启动）
         ├─ ⑤ server.Start()             running=true，级联 Start 全部 feature
         └─ ⑥ 阻塞等 SIGINT/SIGTERM → defer server.Close() 级联关闭
```

## 1. 命令入口（main/main.go）

- `main.go` 只有 17 行：注册 `run`/`version`/`test` 三个子命令后 `base.Execute()`。
- `import _ "main/distro/all"` 是**副作用导入**——所有内置组件的 `init()` 在这里被触发。
- `run` 排第一靠 `runIsTheFirst`（无参数时默认执行 run）。

## 2. 配置文件定位（run.go: getConfigFilePath）

优先级从高到低，全落空则退化为 **stdin**：

1. `-c/-config` 显式文件（已在 configFiles）
2. `-d/-confdir` 目录扫描（按 format 对应扩展名，`-r` 递归）
3. 环境变量 `v2ray.location.confdir` 目录
4. 当前工作目录 `./config.json`
5. 环境变量 `v2ray.location.config` 指向的文件

## 3. 配置加载（根 config.go: LoadConfig）

```
core.LoadConfig(format, files)
  ├─ 无输入 → 用 os.Stdin
  ├─ auto + 单文件 → loadSingleConfigAutoFormat()   按扩展名/内容嗅探格式
  └─ 其他 → 查 configLoaderByName 注册表
        └─ loader 由 main/formats 的 init() 注册（json/toml/yaml）
```

**JSON 加载器内部**（`infra/conf/serial/loader.go`）：

```
DecodeJSONConfig: reader → v4.Config        ← JSON 中间结构（infra/conf/v4）
       │        (DecodeJSON 包了自定义 Reader，报错能定位到 行:列)
       ▼
jsonConfig.Build() → *core.Config           ← 转 protobuf，这才是运行时认的格式
```

要点：**JSON 只是前端**。v4.Config 是带手写 tag 的中间结构，`Build()` 负责翻译成 proto；多文件场景先合并成 map（`infra/conf/mergers`）再走同样路径。

## 4. Instance 装配（v2ray.go:181 New → initInstanceWithConfig）

```go
initInstanceWithConfig 五步：
 1. 建 RootEnvironment（网络 Dialer/Listener、文件系统、持久/临时存储）
 2. 遍历 config.App（protobuf oneof 列表）:
      serial.GetInstanceOf(anyproto) → CreateObjectWithEnvironment
      → common.CreateObject(ctx, config)          ← 查注册表构造
      → 若实现了 features.Feature → AddFeature
 3. 补兜底 feature（用户没配就给默认）:
      localdns / policy.DefaultManager / routing.DefaultRouter / stats.NoopManager
 4. 检查 featureResolutions 非空 → "not all dependency are resolved" 报错
 5. addInboundHandlers / addOutboundHandlers → 挂到 inbound/outbound Manager
```

**注册表机制**（`common/type.go`，全文只有 35 行，值得精读）：

```go
var typeCreatorRegistry = make(map[reflect.Type]ConfigCreator)

RegisterConfig(config, creator)   // key = 配置 proto 的 reflect.Type
CreateObject(ctx, config)         // 按 config 类型查表 → creator(ctx, config)
```

**真实注册例子**（`proxy/freedom/freedom.go:24`）：

```go
func init() {
    common.Must(common.RegisterConfig((*Config)(nil),
        func(ctx context.Context, config interface{}) (interface{}, error) {
            h := new(Handler)
            // 声明依赖：policy.Manager 和 dns.Client，齐备后回调 Init
            core.RequireFeatures(ctx, func(pm policy.Manager, d dns.Client) error {
                return h.Init(config.(*Config), pm, d)
            })
            return h, nil
        }))
}
```

三个惯用法：
- `(*Config)(nil)`：只借类型不造实例（配合 `reflect.TypeOf`）。
- `common.Must`：init 阶段失败直接 panic，**fail fast**——进程带病启动不如不起来。
- 构造函数里用 `RequireFeatures` 声明依赖，把"我现在还缺什么"交给 Instance 排期。

## 5. 启动与关闭（run.go + v2ray.go）

- `server.Start()`：`running=true` → 遍历 feature 级联 `Start()`；之后 `AddFeature` 进来的新 feature 会**热启动**。
- `runtime.GC()`：清掉配置加载阶段（protobuf 反射）的垃圾再进稳态。
- 关闭：无"第二次信号强杀"保护，`Close()` 卡住进程就退不出去（已知局限）。

## 本课小结（面试级一句话）

> v2ray 的启动 = **空白导入触发 init() 注册** → **LoadConfig 把 JSON 翻译成 protobuf** → **core.New 按配置类型查注册表造 feature、用反射解析依赖** → **Start 级联拉起全部 feature**。

## 课后练习（自测）

1. 为什么 `distro/all/all.go` 全是 `_ import`？去掉某个导入会发生什么？
   （答：组件不再注册，启动时 `CreateObject` 查不到对应配置类型而报 "not registered"。）
2. `RequireFeatures` 的回调为什么可能不立刻执行？
   （答：依赖未注册时挂到 `featureResolutions`，等 `AddFeature` 时重试 resolve。）
3. 如果想新增一种出站协议，最少要动哪几个地方？
   （答：新目录写协议实现 + `config.proto` + init 里 RegisterConfig + `all.go` 加空白导入 + `infra/conf` 加 JSON 解析。）
