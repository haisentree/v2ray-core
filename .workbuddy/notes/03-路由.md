# 03 - 路由：PickRoute 与规则匹配体系

> 走读时间：2026-10-22
> 涉及文件：`app/router/router.go` / `config.go` / `condition.go` / `condition_geoip.go` / `balancing.go`
> 场景延续：dispatcher 的 `routedDispatch` 调 `d.router.PickRoute(...)`（02 课 Step 4）

## 一、Router 的两大阶段：编译期 vs 运行期

**编译期（Init，router.go:36）**——启动时把 protobuf 规则一次性编译成内存结构：

```go
for _, rule := range config.Rule {
    cond, err := rule.BuildCondition()   // 规则 → matcher 链
    r.rules = append(r.rules, &Rule{Condition: cond, Tag: ..., Balancer: ...})
}
for _, rule := range config.BalancingRule {
    balancer.Build(ohm, dispatcher); r.balancers[rule.Tag] = balancer
}
```

**运行期（PickRoute，router.go:76）**——每条连接一次，只做匹配，零配置解析（见上图流程）。

路由器注册时的依赖（router.go:172）：`dns.Client + outbound.Manager + routing.Dispatcher`——注意 Router 也依赖 Dispatcher（balancer 的 fallback/observatory 要用）。

## 二、domainStrategy：三种 DNS 策略（pickRouteInternal, router.go:101）

| 策略 | 行为 |
|------|------|
| `AsIs`（demo 配置用的） | 只用现有信息匹配，不碰 DNS |
| `IpOnDemand` | 匹配前就把域名解析成 IP（ctx 挂 `routing_dns.ContextWithDNSClient`），IP 规则直接生效 |
| `IpIfNonMatch` | 先按域名/端口匹配一轮；全不命中**且目标有域名**时，解析出 IP **重跑一遍规则** |

细节彩蛋：`SkipDNSResolve`（:105）——DNS 模块自己发出的查询（比如 DoH 远端是域名）会带上这个标记，防止"解析域名要用 DNS → 查 DNS 又要解析域名"的死循环。

**规则顺序敏感**：顺序遍历、第一条命中即返回。所以"具体规则在前、兜底规则（port 0-65535）在后"。

## 三、规则 = ConditionChan：AND 嵌 OR

`BuildCondition`（config.go:39）：一条 routing rule 的每个字段各生成一个 matcher，全部塞进 `ConditionChan`：

```go
// ConditionChan.Apply: 顺序执行，任何一个 false 即整条不命中（AND）
// 同一字段内多个值：任一匹配即 true（OR）
```

demo 配置验证：规则 1 `{ip:[geoip:private], outboundTag:direct}` → 1 个 matcher；若同时写了 `domain+ip+port` → 三个 matcher 全过才算命中。

## 四、Matcher 家族全览（condition.go）

| Matcher | 实现 | 亮点 |
|---------|------|------|
| `DomainMatcher` | `strmatcher.IndexMatcher`（linear 或 **mph 最少完美哈希**，`domainMatcher:"mph"` 开启） | 四种类型：plain 子串 / regex / **rootDomain 后缀匹配** / full 精确 |
| `MultiGeoIPMatcher` | `netipx.IPSet`（IP 区间集合，Contains 是区间二分/位图） | 按 (国家码,反向) 缓存在 `globalGeoIPContainer`，多个规则引用同一国家不重复构建；`inverseMatch` 支持取反 |
| `PortMatcher` | `net.MemoryPortList` | 区间命中 |
| `NetworkMatcher` | **`[8]bool` 数组当位图**（`v.list[int(network)]`） | 网络 enum 转下标，O(1) |
| `UserMatcher` / `InboundTagMatcher` / `ProtocolMatcher` | 字符串遍历 | Protocol 用 HasPrefix |
| `AttributeMatcher` | **内嵌 Starlark 解释器**（Google 的 Python 方言） | `attributes` 规则写表达式如 `attrs["email"].endswith("x.com")`——配置里跑脚本 |

geosite 数据在**配置期**就被 `geoLoader.LoadGeoSiteWithAttr("geosite.dat", "cn")` 展开成 `[]*Domain` 塞进 DomainMatcher；geoip 同理展开成 CIDR → IPSet。运行期没有任何文件 IO。

## 五、Balancer：一个 tag 背后的一组出站（balancing.go)

```
rule 命中 → GetTag()
   ├─ 无 Balancer → 固定 r.Tag                    config.go:27
   └─ 有 Balancer → PickOutbound():
        ① SelectOutbounds(): ohm.Select(selectors)  ← 按 tag 前缀筛候选
        ② override 有值 → 直接用（gRPC API 可强制指定某出站）
        ③ strategy.PickOutbound(candidates)
             random / leastload(按负载采样) / leastping(按测速延迟)
        ④ 失败或空 tag → fallbackTag 兜底
```

`Route.GetOutboundTag()` 返回最终 tag，dispatcher 拿去 `ohm.GetHandler(tag)`——与 02 课 Step 4 接轨。

## 六、串回主线（demo 配置视角）

```
socks 收到 example.com:443（嗅探还原的域名）
  → PickRoute（domainStrategy=AsIs，不碰 DNS）
  → 规则1: geoip:private？目标没 IP，matcher 直接 false
  → 规则2: port 0-65535？命中 → tag="block"
  → ohm.GetHandler("block") → blackhole 黑洞
（若删掉规则2 → ErrNoClue → 默认出站 direct）
```

## 速记 + 自测

> **速记**：`规则启动期编译成 matcher 链，运行期顺序匹配第一条命中即赢；AND 嵌 OR；IpOnDemand 先解析、IpIfNonMatch 后补解析；Balancer = 前缀选池 + 策略挑一个。`

1. 为什么 `IpIfNonMatch` 要"重跑一遍"规则而 `IpOnDemand` 不用？
   （答：IpOnDemand 在第一遍匹配前就解析好了，IP 规则第一遍就能命中；IpIfNonMatch 期望域名规则先赢，只有全输才值得花一次 DNS 查询。）
2. geoip.dat/geosite.dat 什么时候读？
   （答：配置加载期（BuildCondition 之前），运行期只用编译好的 IPSet/DomainMatcher，零文件 IO。）
3. 两条规则 `domain:[geosite:cn]→direct` 和 `ip:[geoip:cn]→direct` 谁先谁后有区别吗？
   （答：有。若目标只有域名：前者直接命中；后者在 AsIs 下 GetTargetIPs 为空永远 false，在 IpIfNonMatch 下触发一次多余 DNS 解析后命中——后者靠后更省钱。）
