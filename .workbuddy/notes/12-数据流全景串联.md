# 12 - 数据流全景串联：从一根字节到另一根字节

> 时间：2026-10-22。综合笔记 00-11 的收官串联，配全景图（见对话）。
> 场景：客户端经 socks 进来，嗅探到域名，路由命中规则，vmess+WS+TLS 出站。

## 纵向五层旅程

### L1 入站层（被动守门）— 04·07

```
listener Accept（04 课 listener 表 → tls.Server 洋葱包装）
→ tcpWorker.callback（07 课）：造 session.Inbound{Source,Gateway,Tag} + SniffingRequest 入 ctx
→ socks.Process（02 课 Step1）：SOCKS5 握手 → 解出 dest
```
本层职责：**把"一个内核连接"翻译成"带元数据的 ctx + 已知目标"**。

### L2 分发层（数据枢纽）— 02·05b·08·11

```
dispatcher.Dispatch：getLink 造双管道（05b 的 2K 池 buf），立即返回 inboundLink
嗅探 goroutine：cachedReader 偷看首包（不消费）
   → fakedns 引擎（11 课）先试：目标 IP 在 198.18/15 池 → 直接反查域名，0 字节
   → 不行再跑 TLS/HTTP 状态机（08 课三态）→ 改写 dest
```
本层职责：**把入站和出站彻底解耦成"只认管道的两端"**，并顺手把 IP 还原成域名。

### L3 路由层（决策）— 03·11

```
router.PickRoute：预编译 matcher 顺序匹配 → tag
需要 IP 时（IpOnDemand / IpIfNonMatch 二次匹配）→ DNS LookupIP
   → hosts → 域名规则排 client → 逐个查询换下一个 → expectIPs 防污染（11 课）
```
本层职责：**决策**。它的输入质量取决于 L2 嗅探和 DNS 的输出质量——三层是上下游关系。

### L4 出站层（主动出击）— 09·10·05

```
Handler.Dispatch（09 课）：可选域名解析 / mux 分流（10 课 ClientManager）
→ proxy.Process(ctx, link, h)：协议加密封装（05 课 vmess 单包认证 / trojan hash 前缀）
→ h.Dial 五关：链式代理 → tun → UDP → Via/Resolver → internet.Dial
```
本层职责：**把"去 dest 的意图"变成"一条真实（或复用/链式）的连接"**。

### L5 传输层（洋葱包装）— 04

```
internet.Dial 查 dialer 表 → streamSettings 选 tcp/ws/grpc
→ security engine 包 TLS/utls → DialSystem 真 syscall
```
本层职责：**给字节找一条物理出路**，协议层完全不知道底下是什么。

## 回程（图中右侧红色虚线）

远端响应 → conn → downlinkWriter → downlink pipe → socks 的 responseDone → 客户端。
**每一层只认 Reader/Writer，回程无需任何额外代码**——管道对称性的红利。

## 横切系统（不在这条竖线上）

1. **ctx 漂流**：session.Inbound（L1 造）→ SniffingRequest（L2 读）→ session.Outbound.Target（L2 改写、L3 决策、L4 加密）→ log.AccessMessage（一路记录）
2. **stats 三粒度**：conn 级装饰（L1 worker / L4 Dial）+ pipe 级装饰（L2 getLink 的 SizeStatWriter）
3. **policy**：超时/限速在每个 buf.Copy 的 timer 里生效

## 两条隐形通道 + 一根接力棒

- **pipe = 数据面**：所有字节只经它流动，所有解耦都靠它实现（入站↔出站、mux 会话、链式代理）
- **ctx = 控制面**：所有元数据只在它里漂流（开关、目标、用户、日志）
- **接力棒 = session.Outbound.Target**：L2 嗅探可能改写它 → L3 依据它决策 → L4 协议加密它 → L5 传输它

## 一次失败的旅程（反向理解）

链式代理超时 / 目标不可达时：
freedom Dial 失败 → Interrupt link.Writer（09 课惯例）→ socks 侧 buf.Copy 报 writeError
→ task.Run 返回 → conn.Close → 客户端看到连接重置。
**错误沿管道逆向传播，与数据同路反向**——这就是 readError/writeError 分类（05b）的意义。

## 终极速记

> **一个连接进门，一个 ctx 漂流，两根管道接力，五层各司其职；SniffingRequest 是钥匙，Outbound.Target 是接力棒，Reader/Writer 是通用语言。**
