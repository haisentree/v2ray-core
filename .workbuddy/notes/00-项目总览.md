# 00 - 项目总览

> 学习对象：v2ray-core（v2fly 社区维护的 V5 版本），Go 1.26，MIT 协议
> 整理时间：2026-10-20（导览）/ 2026-10-22（成文）

## 一句话理解

V2Ray 内核 = **"协议转换 + 流量调度"引擎**：
接收某种协议的入站连接 → 还原出真实目标地址 → 按路由规则挑一个出站 → 用另一种协议加密转发出去。

## 架构与数据流（自上而下）

```
                    客户端（浏览器/App）
                          │ ① 代理请求
                          ▼
        ┌───────── proxy/ 入站协议 Inbound ─────────┐
        │        socks        http      dokodemo    │
        └──────────────────┬────────────────────────┘
                           │ ② 还原目标地址
                           ▼
        ┌────────── app/ 分发与路由 ────────────────┐
        │   Dispatcher 流量分发    Router 规则匹配   │
        └──────────────────┬────────────────────────┘
                           │ ③ 按规则选出站
                           ▼
        ┌───────── proxy/ 出站协议 Outbound ────────┐
        │  freedom(直连)  vmess  vless  trojan ...  │
        └──────────────────┬────────────────────────┘
                           │ ④ 建立出站连接
                           ▼
        ┌───── transport/internet 传输承载 ─────────┐
        │   TCP   WebSocket   gRPC   QUIC  (+mKCP)  │
        └──────────────────┬────────────────────────┘
                           │ ⑤ 加密隧道流量
                           ▼
                  远端服务器 / 目标网站

  底座：common/ — buf 缓冲 · net 地址 · session · crypto · log
  容器：core.Instance — Feature 注册 + 反射依赖注入（v2ray.go）
```

## 目录导览（按学习重要性）

| 目录 | 职责 | 备注 |
|------|------|------|
| `v2ray.go` / `core.go` | `Instance` 运行时容器：注册 Feature、反射依赖解析 | 核心中的核心 |
| `features/` | **只放接口定义**（dns/routing/inbound/outbound/stats…） | 接口与实现分离 |
| `proxy/` | 协议实现：入站 socks/http/dokodemo；出站 freedom/vmess/vless/trojan/ss2022/wireguard/hysteria2 | 每个协议一个目录 |
| `app/` | 上层功能：dispatcher（枢纽）、router（规则）、dns、proxyman、stats、commander（gRPC 管理 API） | |
| `transport/` | 底层承载：TCP/mKCP/WS/gRPC/QUIC/HTTPUpgrade… | |
| `infra/` | 配置管线：`conf`(JSON 中间结构) → protobuf → 运行时配置 | |
| `main/` | 入口：run/version/test 命令；`distro/all/all.go` 是装配清单 | |
| `common/` | 基础库：`buf` 高性能缓冲、`net` 地址抽象、`session`、`crypto`、`log` | |

## 三个核心设计

1. **Feature + 依赖注入**（`v2ray.go`）
   - `Instance.AddFeature()` 注册功能；`RequireFeatures(callback)` 用反射收集依赖类型，依赖齐备时才回调装配，未就绪则挂到 `featureResolutions` 等待。
   - 装配结束时若仍有未满足依赖 → `initInstanceWithConfig` 直接报错 "not all dependency are resolved"。
2. **protobuf 为配置中心**
   - 每个模块目录都有 `config.proto`；JSON/TOML/YAML 只是前端格式，最终都转成 proto。
   - 收益：天然支持 gRPC API 动态增删 handler、改配置。
3. **全局组件注册表**（`common/type.go`）
   - `typeCreatorRegistry: map[reflect.Type]ConfigCreator`：key = 配置 proto 类型，value = 构造函数。
   - 各包在 `init()` 里调 `common.RegisterConfig((*XxxConfig)(nil), creator)` 注册。
   - `common.CreateObject(ctx, config)` 按配置类型查表构造对象。
   - 装配清单 = `main/distro/all/all.go` 的空白导入（触发各包 init）。

## 学习路径（约定）

1. **启动流程**：`main/main.go` → `distro/all/all.go` → `infra/conf` → `v2ray.go New()` ← *见笔记 01*

3. **路由**：`app/router` + `features/routing`
4. **传输层抽象**：`transport/internet` 的 dialer/listener 注册机制
5. **进阶**：vmess/vless 加密协议、`common/buf` 零拷贝缓冲
